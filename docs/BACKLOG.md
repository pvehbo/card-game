## B · 新功能（框架完成后，按依赖顺序）

### B-1 费用体系（v1.2 首选，解锁“真炉石”节奏）

- 前置：A1（校验）、A5（JSON 已有 `cost` 字段占位）。
- 内容：每回合费用上限（如 1 费开局、每回合 +1、上限 10）；`ActionValidator` 从“次数限”升级为“次数限 + 费用”；手牌 UI 显示费用，不够费置灰。
- 验收：老卡（cost 0）行为不变；新费用单测（不够费拒绝/回合刷新/上限封顶）；AI 会留费/跳过。
- 量级：1～2 天。

### B-2 第一批关键词（v1.2，和费用一起构成“策略深度”）

- 前置：A4（注册表 + 触发点）。
- 内容（按顺序，一个一个加）：冲锋（上场即攻）→ 嘲讽（必须先打）→ 战吼（上场触发）→ 亡语（阵亡触发）。
- 每个关键词固定 3 步：`Keyword` 加枚举 → 新建 `XxxEffect` → 单测（触发 + 不触发）。
- 红线：`CombatResolver` 里禁止单卡特例 `if`。
- 量级：每个半天，共约 2 天。

### B-3 卡牌扩展包 20～30 张（v1.2，和 B-2 同步）

- 前置：A5（JSON 管线）、B-2（关键词就绪）。
- 内容：随从/法术/宠物按费用曲线铺（参考 `BalanceCheck` 同费 ±1）；每张配程序化卡面先行，有美术再替换（走回退链）。
- 验收：`CardDatabase` 校验过；`autoplay=20`×5 局无异常；胜率统计留档。
- 量级：2～3 天（含数值调参）。

### B-4 AI 难度分级（v1.2 收尾，留住不同水平玩家）

- 前置：A6（接口）、B-1/B-2（AI 要懂费用和关键词）。
- 内容：简单（随机合法动作）/ 普通（现有贪心）/ 困难（贪心 + 斩杀预判 + 解嘲讽优先级）；难度做成下拉选择，一局内可换。
- 验收：三难度 `autoplay` 胜率呈阶梯（简单 < 普通 < 困难 vs 同一基准）；`AiNoCheatTest` 保持绿。
- 量级：1～2 天。

### B-5 本地双人对战——已取消（方向：纯单机）

> 决策：不做本地双人，专注单人游玩。联机对战（B-10）保留，但只预留接口、
> 现在不实现。预留的 seam（已就绪，无需加代码）：
> - 同步单元 = `GameSession`（双方状态 + 轮到谁，纯数据，可序列化）
> - 线路协议 = `GameEvent` JSON（`EVENT_SCHEMA` 版本化，S9 已锁往返）
> - 走子校验 = `ActionValidator.legalActions`（服务端收到指令重算一遍即可反作弊）
> - 确定性 = `Deck.shuffle(Random)` 可定种子（联机掷骰可复现/仲裁）
> 将来做联机时，服务端 = 会话 + 校验 + 事件广播三件套，客户端不动结算。

### B-6 存档 / 读档 / 战局回放（v1.3，含“后悔药”和传播素材）

- 前置：A8（存档服务）、A9（事件序列化）。
- 内容：回合结束自动存档；读档续玩；回放 = 事件流重播（可加速/暂停，给截图和战报用）。
- 验收：存档→读档→终局与原局一致；上版本存档可迁移读入。
- 量级：2 天。

### B-7 牌组构筑器（v1.3，卡多之后的刚需）

- 前置：A5（卡库）、A7（界面）。
- 内容：30 张牌组（同名上限 2 张）；构筑页列表 + 搜索 + 费用曲线图；非法牌组禁止开局并提示原因。
- 验收：构筑→开局→终局全链路；非法牌组 3 种提示（超量/不足/禁卡）单测。
- 量级：2～3 天。

### B-8 数据与成就——已跳过（暂不做）

- 前置：A8（日志/配置）。
- 内容：总胜率、先手/后手胜率、最高连击/连胜；成就 5～8 个（首胜/十连胜/空场斩杀等），本地存。
- 量级：1 天。

### B-9 美术/音效资源包（穿插做，不阻塞）

- 前置：回退链测试（A8 已含）。
- 内容：成套卡图、英雄头像、战场背景、主题 CSS（亮/暗两套）；替换即生效，删除即回退。
- 量级：随资源进度，不占程序关键路径。

### B-10 联机对战（v2.0，明确最后做）

- 前置：全部 A + 需要**新增网络同步方案**（状态同步 vs 指令同步选型、断线重连、反作弊；seam 见 B-5）。
- 联机单独立项估算，不混在本轮。
- 量级：4 周起，另行计划。

### B-11 卡牌编辑器 / 排位天梯（v2.0+，看留存再定）

- 做之前先看 v1.3 的数据（对局数、卡组多样性）；两者都不阻塞现在任何工作。
