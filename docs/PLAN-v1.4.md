> 实施记录见 `docs/CHANGELOG.md` v1.4.0 节；本文档留档作为规划底稿，后续规划参考 §4（v1.5 美术版 / v2.0 联机版）。

> 配套文档：`docs/BACKLOG.md`（总清单）、`docs/CHANGELOG.md`（版本记录）、`docs/BALANCE.md`（数值规范）。

## 0. 现状盘点（为什么是这个版本）

v1.3 交付后，项目状态：

| 维度 | 现状 | 短板 |
|---|---|---|
| 框架 | A0～A10 全部落地（校验器/结算器/会话/效果管线/AI 接口/MVVM/服务层/CI 三端） | 无，冻结不动 |
| 玩法 | 费用体系 + 冲锋/嘲讽/战吼/亡语 + 三级 AI | 关键词只有 4 个战斗关键词，卡池仅 20 种（11 随从/5 法术/4 宠物），三局见底 |
| 留存 | 无存档外任何长期目标（B-8 被跳过） | 玩家赢一局就走，没有"再来一局"的理由 |
| 门面 | README 停在 v1.0 规则（20 血、无费用、单一 AI） | 与实现严重脱节，误导新玩家 |

**结论**：框架红利还没吃完。`Keyword → Effect/Trigger → 单测` 流水线、`BalanceCheck` 体检、`AiLadderTest` 天梯基准都是现成的，扩内容边际成本极低。v1.4 把这些红利兑现，**不做任何新系统**（不做装备/任务/副本，不做本地双人）。

## 2. 工作项详案

### W0 README 重写（半天）

**问题**：README 的"玩法规则"还是次数限时代（每回合出 1 随从/1 法术/1 宠物），没有费用、关键词、AI 难度、构筑器、存档回放。

**步骤**：
1. 以 `docs/CHANGELOG.md` v1.1～v1.3 为事实源重写玩法规则（费用 1 费开局/+1 每回合/10 封顶；冲锋/嘲讽/战吼/亡语词条解释）。
2. 补三节：AI 难度选择（下拉/`-Dai.level`）、牌组构筑器（30 张/同名≤2/明星单卡≤1）、存档与回放。
3. 更新截图：`java -Dui.screenshot=docs/screenshot.png -cp "target/classes:$(cat target/cp.txt)" org.example.card.ui.Main`。
4. 核对技术栈与项目结构两节，补齐 `data/`、`effect/`、`service/` 包说明。

**验收**：README 中每一条规则都能在代码或测试里找到对应；无 v1.0 残留表述。

### W1 数据统计 + 成就（1 天）

**前置**：A8 已交付 `ConfigService`（文件配置）与 `GameLog`（文件日志），`UserData.dir()` 提供数据目录——零新基建。

**内容**：

1. **`service/StatsService`**（新建）：
   - 持久化到 `~/.cardgame/stats.json`（版本化字段，未知字段忽略——沿用 `SaveService` 的兼容策略）。
   - 记录：总场次/胜场、按 AI 难度分组胜率、先手/后手胜率、当前连胜与最高连胜。
   - 数据源：订阅 `GameEventBus` 的胜负事件，**只读事件不改引擎**。
2. **成就 8 个**（本地判定，弹 toast + 落盘）：

   | 成就 | 条件 |
   |---|---|
   | 初露锋芒 | 首次获胜 |
   | 乘胜追击 | 三连胜 |
   | 十连绝世 | 十连胜 |
   | 空手而归 | 空手牌获胜 |
   | 满门抄斩 | 一回合清空对方 ≥4 随从 |
   | 绝地反击 | 己方英雄 ≤5 血时反杀获胜 |
   | 巨人杀手 | 击败困难 AI |
   | 老谋深算 | 单局打满 15 回合后获胜 |

3. **UI**：主界面加"战绩"按钮，弹窗展示统计表 + 成就列表（未解锁置灰）。

**验收**：
- 单测：构造事件流喂给 `StatsService`，断言统计数字与成就触发（触发/不触发各一例）。
- 兼容测试：上版本 `stats.json` 可迁移读入（参照 `SaveCompatTest` 模式）。
- 删 `stats.json` 正常开局（从零计数，不崩）。

**红线**：`StatsService` 只订阅事件，禁止反向调用 `GameEngine`；成就判定逻辑必须可在无 UI 环境跑（toast 只是订阅者之一）。

### W2 第二批关键词（每个半天，共 1.5 天）

**前置**：A4 效果管线 + B-2 关键词机制已就绪。每个关键词严格走既有三步流水线：

```
Keyword 加枚举 → 新建 XxxEffect / 挂 TriggerSystem → 单测（触发 + 不触发）
```

| 关键词 | 语义 | 落点 | 复杂度 |
|---|---|---|---|
| **DIVINE_SHIELD 圣盾** | 抵消第一次受到的伤害 | `CombatResolver` 伤害入口加单次豁免标记（状态放随从实例，不进 resolver 特例 if——用 `Keyword` 查询 + 计数器字段） | 中 |
| **WINDFURY 风怒** | 每回合可攻击 2 次 | `ActionValidator` 出手次数校验从 1 放开到关键词判定 | 低 |
| **POISONOUS 剧毒** | 对随从造成伤害即摧毁（不论血量） | `CombatResolver` 阵亡判定分支 | 低 |

**数值口径**（写进 `BalanceCheck`）：圣盾、风怒按 2 点价值计入（与冲锋/嘲讽同权），剧毒按 3 点（机制强但怕圣盾/低攻换）。

**验收**：
- 每个关键词：`KeywordMechanicsTest` 风格的新单测（触发 + 不触发 + 与嘲讽/冲锋的交互各一例）。
- `BalanceCheckTest` 零告警。
- **红线沿用 B-2**：`CombatResolver` 里禁止单卡特例 `if`，全部走关键词查询。

### W3 卡池扩容 20 → 30 种（2 天）

**前置**：W2 完成（新卡要用新关键词）。

**内容**：新增 10 种卡，按费用曲线铺平（当前 1～2 费和 5+ 费断层）：

| 费用 | 新增 | 定位 |
|---|---|---|
| 1 费 | 随从×2 | 快攻起手（其中 1 张剧毒小随从，低攻高威慑） |
| 2 费 | 随从×1 + 法术×1 | 风怒随从；小 AOE 或单解法术 |
| 3 费 | 随从×1 + 宠物×1 | 圣盾随从；进攻向宠物 |
| 4 费 | 随从×1 + 法术×1 | 战吼抽牌随从；中期解场 |
| 5～6 费 | 随从×1 | 圣盾+嘲讽大哥，终结手段 |

**方法**（沿用 B-3 流程）：
1. 写进 `resources/cards/*.json`（明星单卡 `copies: 1`，普通卡 ≤2）。
2. `CardDatabase` 启动校验（fail-fast 到文件:行，已有）。
3. `BalanceCheck` 体检零告警；超标卡必须配副作用（B-3 定的规矩：超模配毒）。
4. 程序化卡面先行，不阻塞；美术走 B-9 回退链后补。

**验收**：
- `autoplay=20` × 5 局无异常，战报留档 `docs/`。
- 新卡在 AI 三档下都被实际打出过（战报 grep 验证，防止"设计了但 AI 不会用"）。
